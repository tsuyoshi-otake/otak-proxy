# Windows プロキシ環境変数の不一致通知

## 要件と承認

ユーザー依頼「設計してIssueにして対応」と、その後の「検出・適用は従来どおりにして、食い違いを通知する」という選択に基づく。対象言語は日本語。要求・設計・実装作業をこの範囲で進める。

- ローカル Windows のユーザー・システム環境変数と拡張ホストの環境を比較する。
- HTTP_PROXY、HTTPS_PROXY、ALL_PROXY、NO_PROXY を扱い、Windows の大文字小文字を区別しない。
- Auto の検出順位・適用・Off の動作、OS の環境変数を書き換えない。
- 値や認証情報を通知・ログ・永続状態に出さない。
- 通知は完全終了後の VS Code 再起動とターミナルの開き直しを案内する。ウィンドウ再読み込みによる反映は保証しない。

## 設計

### 読み取り境界

専用の読み取りモジュールが Windows PowerShell を非対話・プロファイルなし・非表示・5 秒タイムアウトで実行する。固定スクリプトから .NET Environment.GetEnvironmentVariable の User / Machine を指定し、対象 4 変数だけを JSON で返す。値をコマンドに埋め込まない。JSON の完全な構造を検証し、失敗・タイムアウト・アクセス拒否・部分結果は「不明」として比較しない。

API 契約: https://learn.microsoft.com/en-us/dotnet/api/system.environment.getenvironmentvariable

### 比較規則

変数ごとにユーザー設定をシステム設定より優先する。保存値が存在し、プロセスの値と異なるとき通知対象とする。保存値を一度観測した変数は、後の削除も比較対象とする。起動前に削除された値とプロセス限定の明示設定は区別できないため、初回から保存値がない変数には通知しない。下位のシステム値だけが変化し、優先されるユーザー値が同じなら通知しない。

### ライフサイクルと負荷

通知用監視は検出・適用とは独立する。起動直後に非同期確認し、完了後 60 秒間隔で再確認する。ローカル Windows のみで動作し、リモート拡張ホストでは起動しない。非フォーカス中の確認は起動時も含め省略する。重複実行を避け、失敗時は指数バックオフとジッターで最大 15 分まで間隔を広げる。dispose はタイマーと実行中プロセスを停止し、遅延結果の通知を抑止する。

不一致内容の SHA-256 をメモリ内に保持して同じ不一致の通知を抑制する。通知は最大 5 分に 1 回とし、抑制された新しい内容は次の確認で再判定する。ユーザーが通知を閉じるまで監視を待たせない。通知レベル off では通知しない。

## 作業と検証基準

- [x] 読み取り境界と比較・監視を実装する。
  - Verify: WindowsProxyEnvironment 単体テスト。
  - Expect: 優先順位、追加・変更・削除、空値、大文字小文字、資格情報、失敗、復旧、並行確認、dispose が通る。
- [x] 拡張機能の起動・終了と多言語通知を接続する。
  - Verify: 隔離 VS Code ホストの WindowsProxyEnvironment 統合テスト。
  - Expect: 通知文・非同期起動・通知抑制・既存検出結果不変・実 PowerShell の読み取りが通る。
- [x] 回帰確認と証跡を記録する。
  - Verify: compile、lint、関連の検出・ターミナル単体テスト、テスト終了後のプロセス一覧。
  - Expect: 全て成功、対象 runner の残存 0。

## 検証範囲の限界

OS の保存値変更は決定的な疑似応答で検証し、開発者の環境変数は変更しない。実 PowerShell 境界は読み取りのみ検証する。管理ポリシーや親ランチャーが古い環境を保持する場合、完全終了後も再起動元の更新や再サインインが必要になる可能性がある。REG_EXPAND_SZ の参照先は Windows/.NET の展開規則に従う。
